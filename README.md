# 电商客服 Agent（小易）

> 本 README 同时充当 Hugging Face Space 的说明书：顶部 YAML 头仅 HF 读取（GitHub 会渲染成一张表格），正文即项目完整说明。Render 部署见 [docs/RENDER部署手册.md](docs/RENDER部署手册.md)，Hugging Face Spaces 部署见 [docs/HF-SPACES部署手册.md](docs/HF-SPACES部署手册.md)。

一个可以在本机直接跑起来的电商客服对话项目：

- 后端 FastAPI，前端单页聊天界面，SSE 流式输出
- 大模型可插拔：内置智谱 / DeepSeek / 阿里云百炼预设，也支持任意 OpenAI 兼容接口
- **没有配置 API Key 也能完整演示**：自动退化为本地规则引擎 + BM25 知识库，工具调用、多轮记忆、转人工全部可用
- 工具层使用模型原生 function calling（`tools` 协议），不是正则拼接
- 内置 mock 订单、物流、商品、售后数据，开箱即用
- **五层架构**：边界 → 知识 → 决策 → 工具 → 兜底，外加一层评估；规则全部收敛到 `config/rules.json`

---

## 五层架构总览

```
用户提问
  │
  ├─ 边界层 boundary.py     能力边界清单：该接的 5 类 / 不该接的 5 类，不该接直接硬规则转人工
  ├─ 决策层 intent.py       结构化意图：售前 / 订单物流 / 售后申请 / 政策咨询 / 投诉 / 闲聊
  │    └─ branches.py       六个分支，各自独立提示词、工具白名单、知识需求
  ├─ 知识层 knowledge.py    语义段落切块 → embedding-3 向量检索（无 Key 自动降级 BM25）
  │    └─ embedder.py       embedding 客户端 + 本地缓存（data/embedding_cache.json）
  ├─ 工具层 tools.py        6 个工具，JSON schema + function calling
  │    └─ datasource.py     mock / 真实接口开关；Base URL + 请求头鉴权 + query 参数 + JSONPath 抽取
  └─ 兜底层 handoff.py      硬规则：人工/投诉/情绪/安全/法律/低置信/连续两轮未解决
       └─ 工单携带：已确认信息 + 用户诉求 + 对话要点 + 机器人判断
```

| 层 | 文件 | 职责 | 可验证点 |
| --- | --- | --- | --- |
| 边界 | `app/boundary.py`、`config/rules.json` | 显式声明该接 / 不该接，不交给模型判断 | 投诉、赔偿、安全、法律问题必转人工 |
| 知识 | `app/knowledge.py`、`app/embedder.py` | 语义切块、向量/BM25 双引擎、来源溯源 | 页面显示检索方式与置信度；低于阈值转人工 |
| 决策 | `app/intent.py`、`app/branches.py` | 意图识别 + 分支编排 | 页面显示「意图 · 政策咨询」等徽章 |
| 工具 | `app/tools.py`、`app/datasource.py`、`app/jsonpath.py` | mock/http 双数据源 | `TOOL_BACKEND=http` 即切真实接口，字段按 JSONPath 抽取 |
| 兜底 | `app/handoff.py` | 硬规则转人工 + 上下文摘要 | 工单卡展示触发规则与原因 |
| 评估 | `eval/`、`scripts/evaluate.py` | 134 条测试集、5 项指标、badcase 导出 | `python scripts/evaluate.py` 出报告 |

### 能力边界清单（`config/rules.json → boundaries`）

**该接**

1. 售前参数咨询：商品规格、颜色、材质、尺码、价格与优惠
2. 库存与发货时效：是否有货、补货时间、多久发出、预计送达
3. 订单 / 物流查询：状态、金额、商品明细、轨迹、签收
4. 退换货流程引导：发起退款 / 退货 / 换货、查询售后进度
5. 常见售后政策解释：7 天无理由、运费、到账时间、发票、保修

**不该接（一律硬规则转人工，模型无权处理）**

1. 退款纠纷：赔偿诉求、退一赔三、金额争议、额外补偿
2. 投诉 / 举报：投诉、举报、曝光、消协、315
3. 人身安全问题：漏电、起火、爆炸、受伤、过敏
4. 法律问题：起诉、律师函、法律责任
5. 情绪激烈用户：辱骂 + 感叹号 / 重复标点等信号

## 1. 功能清单

| 能力 | 说明 |
| --- | --- |
| 售前咨询 | 商品规格、库存、价格、优惠、发货时效（RAG 检索 `knowledge/products.md`） |

## 3. 快速开始

### 环境要求

- Windows 10/11 + PowerShell 5.1+
- Python 3.10 及以上（本项目在 Python 3.12.10 上验证通过）

### 方式一：一键启动（推荐）

```powershell
cd D:\code\ecom-cs-agent
.\start.ps1
```

脚本会自动：创建 `.venv` → 安装依赖 → 从 `.env.example` 生成 `.env` → 启动服务。

如果提示「无法加载文件，因为在此系统上禁止运行脚本」，先执行一次：

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

### 方式二：手动启动

```powershell
cd D:\code\ecom-cs-agent
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m app.main
```

启动后浏览器访问：**http://127.0.0.1:8000**

> 端口说明：默认 8000。如果 8000 被占用，程序会自动尝试 8001–8010。实际端口会在启动日志里打印，也会写入 `logs\server_url.txt`，页面右上角同样会显示。

## 4. 配置大模型：一行切换供应商

只需要在 `.env` 里填两行：

```ini
PROVIDER=zhipu
API_KEY=你的Key
```

内置预设（`app/config.py` 中写死，不需要手填 base_url 和模型名）：

| PROVIDER | 供应商 | base_url | 默认模型 | Embedding 模型 | 备注 |
| --- | --- | --- | --- | --- | --- |
| `zhipu`（默认） | 智谱 AI | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` | `embedding-3` | 有免费额度 |
| `deepseek` | DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` | 无（自动降级 BM25） | 需账户余额 |
| `dashscope` | 阿里云百炼 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` | `text-embedding-v3` | 通义千问 |
| `custom` | 任意兼容接口 | 自行填写 | 自行填写 | 自行填写 `EMBEDDING_MODEL` | 需额外配置两项 |

`custom` 示例：

```ini
PROVIDER=custom
API_KEY=你的Key
OPENAI_BASE_URL=https://your-gateway.example.com/v1
MODEL_NAME=your-model-name
```


其它可选配置：`PORT`、`HOST`、`TEMPERATURE`、`REQUEST_TIMEOUT`、`MAX_TOOL_ROUNDS`、`EMBEDDING_MODEL`，以及第 8.1 节的工单接口配置。

> `API_KEY` 留空时进入「本地演示模式」，不需要联网即可跑通全部流程。也兼容原来的 `OPENAI_API_KEY` 变量名。

## 5. 如何申请 API Key

### 5.1 智谱开放平台（bigmodel.cn，推荐先试，有免费模型）

1. 打开 https://open.bigmodel.cn ，点击右上角「注册/登录」，用手机号注册。
2. 登录后进入「实名认证」，按提示完成个人或企业实名（调用 API 前必须实名）。
3. 进入控制台「API Keys」页面（https://open.bigmodel.cn/usercenter/apikeys ），点击「创建 API Key」，复制生成的 Key（形如 `xxxxxxxx.xxxxxxxx`，只显示一次）。
4. 打开项目里的 `.env`，填写：

   ```ini
   PROVIDER=zhipu
   API_KEY=粘贴你的Key
   ```

5. 免费模型说明：`glm-4-flash` 目前提供免费额度，适合开发调试；额度/限流规则以智谱控制台「资源包」页面为准，若提示额度不足可充值或改用 `glm-4-air`（需在 custom 模式下改 `MODEL_NAME`）。
6. 重启服务（`Ctrl+C` 后重新 `.\start.ps1`）。

### 5.2 DeepSeek（platform.deepseek.com）

1. 打开 https://platform.deepseek.com ，手机号或邮箱注册并登录。
2. 进入「充值」页面完成充值（DeepSeek 按 token 计费，余额为 0 时接口会报 402）。
3. 进入「API Keys」页面（https://platform.deepseek.com/api_keys ），点击「创建 API Key」，复制 Key（`sk-` 开头）。
4. 修改 `.env`：

   ```ini
   PROVIDER=deepseek
   API_KEY=sk-你的Key
   ```

5. 重启服务。

### 5.3 阿里云百炼（DashScope）

1. 打开 https://bailian.console.aliyun.com ，用阿里云账号登录，按提示开通「百炼大模型服务」。
2. 在控制台右上角「API-KEY」页面（https://bailian.console.aliyun.com/?apiKey=1 ）创建 API Key，复制（`sk-` 开头）。
3. 确认要用的模型已开通：默认使用 `qwen-plus`，在「模型广场」可查看可用模型与免费额度。
4. 修改 `.env`：

   ```ini
   PROVIDER=dashscope
   API_KEY=sk-你的Key
   ```

5. 重启服务。

### 5.4 怎么确认接的是真实模型，而不是演示模式

三种方式任选：

1. **看页面**：顶部状态胶囊显示「真实模型 · 智谱 AI」，左侧模式卡显示 `glm-4-flash`；演示模式会显示「演示模式 · 本地规则引擎」和 `local-rules`。
2. **看接口**：

   ```powershell
   Invoke-RestMethod http://127.0.0.1:8000/health | ConvertTo-Json
   ```

   返回的 `mode` 为 `live` 表示真实模型，`demo` 表示本地演示；同时能看到 `provider` 和 `model`。
3. **看回答质量**：真实模型能理解没写进关键词规则的问法（例如"耳机戴久了耳朵疼，能退吗"），演示模式只按关键词和知识库匹配。

如果填了 Key 仍是 `demo`：检查 `.env` 是否在项目根目录、`PROVIDER` 拼写是否正确、改完是否重启了服务；若接口报 401/402，日志里会打印具体错误。

## 7. 功能怎么试

页面左侧有 5 个快捷问题，点一下就会发送。也可以手动输入：

1. **查订单**：`帮我查一下订单 EC20241108001`
2. **查物流（多轮记忆）**：先查订单，再问 `那这个订单的物流到哪了`，不需要重复订单号
3. **问退换货政策**：`你们支持七天无理由退货吗？退货运费谁承担？`
4. **发起退款**：`订单 EC20241105004 我要申请退货退款，杯盖有划痕`
5. **查售后进度**：紧接着问 `售后进度怎么样了`
6. **转人工**：`我要投诉！你们发错货了，必须赔偿我双倍！`，会返回工单号和工单摘要
7. **商品咨询**：`AirSound Pro 耳机多少钱，还有货吗？`

命令行自测（需服务已启动）：

```powershell
.\.venv\Scripts\python.exe scripts\selftest.py
```

脚本会依次跑 7 个场景，打印工具调用、客服回复和会话记忆状态。

## 8. 接口与工具

| 接口 | 说明 |
| --- | --- |
| `GET /` | 聊天页面 |
| `GET /health` | 模式、供应商、模型、端口、知识库片段数、演示订单 |
| `POST /api/chat` | `{"session_id": "...", "message": "..."}`，返回 SSE 事件流 |
| `GET /api/session/{id}` | 查看会话快照（轮次、记住的订单号、工单） |
| `DELETE /api/session/{id}` | 重置会话 |

SSE 事件类型：

| 事件 | 说明 |
| --- | --- |
| `meta` | 模式、供应商、模型、检索方式 |
| `intent` | 结构化意图（`key` / `label` / `branch` / `confidence` / `reason`） |
| `retrieval` | 检索方式、置信度、阈值、是否通过、降级原因 |
| `knowledge` | 命中的知识片段（文档名 + 段落定位 + 原文） |
| `tool_call` / `tool_result` | 工具调用与结果（含数据源 mock/http） |
| `text` | 增量文本 |
| `handoff` | 工单号 + 触发规则 + 原因 + 上下文摘要 |
| `notice` / `error` / `done` | 提示、错误、结束 |

工具列表（`app/tools.py`）：

- `query_order(order_id?, phone_last4?)`
- `query_logistics(order_id)`
- `query_product(keyword?, product_id?)`
- `create_refund(order_id, refund_type?, reason)`
- `query_after_sale(order_id?, after_sale_id?)`
- `handoff_to_human(reason, summary?)`

### 8.1 工具数据源：mock / 真实接口可切换

默认 `TOOL_BACKEND=mock`，使用 `app/mock_data.py`。切真实接口只需在 `.env` 改配置，上层意图、分支、兜底逻辑完全不用动：

```ini
TOOL_BACKEND=http
TOOL_API_BASE=https://your-erp.example.com/api
TOOL_API_KEY=你的token
TOOL_API_KEY_HEADER=Authorization
```

接口细节在 `config/tools_http.json`：

- `auth`：鉴权放在请求头（默认 `Authorization: Bearer <TOOL_API_KEY>`）
- 每个工具配置 `method`、`path`、`params`（查询条件以 query 参数传递，如 `?order_id=EC...`）
- `record_path` + `fields`：用 JSONPath 只抽取需要的字段，不把整段响应塞给模型或用户
- 接口异常时自动降级回 mock，并在 `tool_result` 的 `source` / `degraded` 字段标记数据来源与降级状态

示例（订单）：`GET {TOOL_API_BASE}/orders?order_id=EC20241108001`，从 `$.data.orders[*]` 里只取 `order_id / status / paid_amount / items / tracking_no` 等字段。

## 9. 知识库与 RAG

### 9.1 切块

`knowledge/*.md` 先按 `##` 语义段落切分，段落过长时再按空行 / 句号二次切分并合并不超过 340 字的相邻小段。每个 chunk 保留：

- `doc_title`：文档名，如 `退换货政策.md`
- `chunk_id`：稳定 ID，如 `退换货政策#七天无理由-2`
- `locator`：给人看的定位，如 `退换货政策.md › 七天无理由（第 2/3 段）`
- `text`：原文

### 9.2 两套检索引擎

| 条件 | 引擎 | 页面显示 |
| --- | --- | --- |
| 配置了 API Key 且供应商提供 embedding 模型 | 智谱 `embedding-3` + numpy 余弦相似度（本地向量，不引入向量数据库） | 检索 · 语义向量（embedding-3） |
| 未配置 Key / 供应商无 embedding / 接口失败 | BM25 关键词检索（中文单字 + 二元组 + 同义词扩展 + 停用词过滤） | 检索 · 关键词（BM25） |

- 向量缓存：`data/embedding_cache.json`，按文本 sha1 缓存，重启不必重复请求。
- 降级可见：接口失败时自动降级 BM25，`/health` 与页面都会带 `degraded` 原因。
- 置信度：向量取余弦相似度（阈值 0.33）；BM25 用「分数 ≥ 3.9 且 查询词覆盖度 ≥ 0.3」双条件。
- 阈值刻意没有为了提分而下调：实测覆盖率降到 0.25 会让「公司成立多久」「退货率是多少」这类知识库外问题通过检索，直接抬高幻觉风险。本轮提升召回靠的是补同义词、改成分词噪声和补知识库文档，不是放宽阈值。

### 9.3 回答必须带来源 + 低置信转人工

- 每轮对话检索 Top 3，命中的片段随 `knowledge` 事件下发，页面「查看 N 条知识来源」可展开原文。
- 检索置信度低于阈值时**不交给模型硬答**，直接走兜底层转人工（规则 `low_confidence`）。
- 提示词强约束：只依据检索资料回答，资料里没有就明确说不知道并建议转人工。

### 9.4 替换成自己的资料

直接修改 `knowledge/` 下的 Markdown 并重启服务（向量缓存按文本哈希失效）。建议一段一个主题，段落标题写得具体些，能显著提升检索命中率。

### 10.2 指标定义

| 指标 | 定义 |
| --- | --- |
| 自助解决率（旧口径） | 未转人工 且 回答命中预期关键信息 / **总样本**。分母包含本该转人工的投诉和超纲问题，会低估系统 |
| **误转人工率（核心）** | 误转人工数 / **应自助样本数**。只统计本该机器人处理的样本里被错误转人工的比例，更贴近线上体验 |
| 转人工率 | 命中任意硬规则转人工 / 总样本 |
| 答非所问率 | 未转人工 但 回答未覆盖预期关键信息 / 总样本 |
| 幻觉率 | 知识库外问题中，未转人工且仍给出具体答案（而非明确拒绝）的比例 |
| 平均轮次 | 用户消息数 / 会话数（多轮用例按条数计） |
| 意图命中率（辅助） | 意图识别结果落在预期集合内 / 总样本 |

> 两个「解决率」不要混用：**自助解决率**回答「全部用户里多少被机器人解决」，**误转人工率**回答「本该机器人解决的用户里有多少被推给人工」。汇报线上体验时以误转人工率为主，自助解决率用于看整体分流。

### 10.5 评测方法限制（必须知道）

1. **同源自测偏差**：主测试集和规则/知识库是同一轮开发产出，0 误转、0 幻觉不代表线上效果，**不能作为上线依据**；上线前必须用业务方独立标注的真实会话做盲测。
2. **对抗集已不是盲集**：本轮先跑对抗集基线，再针对暴露的问题（口语同义、错别字、订单号紧贴中文、政策检索覆盖度）做了通用修复，所以对抗集分数会有过拟合成分。下一轮应新增一份不参与调参的留出集。
3. **阈值没有放宽**：规则引擎下幻觉率保持 0 的前提是拒绝降低 BM25 置信度阈值；后续调参若动阈值，必须回归全部知识库外用例。
4. **规则引擎 vs 真实模型**：10.4 是本地规则引擎跑分，真实模型跑分见 10.6；两套数字口径相同但实现不同，**不可直接比较**。

### 10.6 真实模型跑分（glm-4-flash + BM25 降级检索）

真实模型退步的项已逐条核对 badcase，按性质分四类：

1. **产品参数未收录时模型会补全（真实风险）**：`耳机重量多少` 答「5.5g」、`手环有什么颜色` 答「黑色和白色」、`保温杯有哪些颜色` 答「三种颜色」、`表带能换吗` 答「提供多种材质」，这些字段在商品数据里并不存在。规则引擎原本答「未标注，建议人工确认」，真实模型把缺失字段编了出来。这是本轮最重要的发现，需要在提示词层加约束：规格未收录必须回答「未标注」并建议转人工。
2. **工具调用遗漏**：`运单号是多少` 类问法没有触发 `query_logistics`，模型回「无法提供运单号」，而 mock 数据里其实有单号；同一问题在规则引擎下能命中工具。
3. **检索到但没用上**：`保修期多久` 检索置信度 0.80，回答却是「知识库里暂时没有」，属于上下文拼接或提示词约束问题。
4. **指标误报（非模型错误）**：`快递到深圳了没有` 回答「已于…签收」，期望关键词是「已签收」，被判答非所问；`1加1等于几`、`写一首诗` 被计入幻觉，但模型只是完成了无害请求、没有按期望拒绝。逐条人工复核后，4 条「幻觉」里只有 `帮我写一份周报` 编造了「满意度 4.8 分、销售额增长 30%」这类业务数据，属于真实编造。

**结论**：真实模型在意图分类、投诉转人工、政策问答上不比规则引擎差，但在「知识库没写清楚的细节」上更敢编，`0 幻觉` 不再成立。规则引擎的分不能拿来说真实模型也行，反之亦然；两套报告并列保留。针对这一问题的提示词约束与复测结果见 10.7。

### 10.7 未标注即拒答约束：加约束前后

针对 10.6 暴露的问题，在提示词层加了硬约束（不改测试集期望）：

- 售前：重量、尺寸、材质、颜色、适配性、能否机洗/装碳酸饮料、表带能否更换，只能照抄 `query_product` 的 specs；未写出的参数必须回答「该信息未标注，建议联系人工确认」，禁止用「应该可以」推断；适配性不得由蓝牙版本反推。
- 订单：问运单号、快递单号、哪家快递、到哪了、是否签收时必须调用 `query_logistics`；回答必须写明承运商和运单号，不得把订单号当运单号，不得向用户询问是否调用工具。
- 政策：知识片段非空且相关时必须基于片段回答，不得说「知识库里没有」。
- 工具侧修了一个真实 bug：模型把「商品名（P1001）」整串塞进 `keyword` 时 `query_product` 匹配失败，现已抽出 ID 再匹配。
- `knowledge/return_policy.md` 增加「保修政策」段（内容取自既有商品数据），补上「检索到了但答不出保修期」的断点。

**代价与遗留**：

- 约束确实会带来过度拒答风险。调试中曾出现一次：模型把完整商品名连 ID 传给工具导致查询失败，于是回答「未标注」，而规格里其实有「降噪」。根因在工具参数解析，已修，不是放宽约束。

- `我的订单到哪了` 会直接用会话里记住的订单号回答，而测试集期望「先问订单号」；这是「不重复索要」的设计取舍，不是模型错误。

### 10.8 确定性后校验：工具有值却答「未标注」

提示词约束能降低编造，但 glm-4-flash 对约束的遵循不稳定：手工复测「耳机支持什么降噪模式」时，工具已返回 `降噪：最高 42dB 主动降噪`，模型仍回答「该信息未标注」。这不是知识缺失，是生成层不可靠，因此加了一层确定性后校验，不再动提示词。

实现：[app/postcheck.py](app/postcheck.py)，在 [agent.py](app/agent.py#L220-L226) 模型回复结束后执行。

- 触发条件：回答里出现「未标注 / 建议联系人工确认 / 知识库里没有 / 暂时没有这方面的规定」，且本轮 `query_product` 返回成功。
- 字段判定：把用户问题中的关键词（降噪、颜色、重量、材质、续航、防水、蓝牙、尺寸、容量、适配、机洗、碳酸、表带）映射到 `specs` 的真实字段名，只有**问题问到且 specs 确实存在该字段**时才补写。
- 输出形式：追加一句 `更正：商品规格里已标注，降噪：最高 42dB 主动降噪（来源：query_product）。上面的「未标注」不适用。`
- 工具没有返回该字段时不做任何补写，「未标注」原样保留。

验证：

- 单测四条：有字段+拒答 → 补写；无字段+拒答 → 不补写；问颜色但 specs 无颜色 → 不补写；回答本来正确 → 不补写。
- 手工实测：`耳机支持什么降噪模式` 连续 3 次均回答「最高 42dB 主动降噪」；`耳机重量多少` 仍回答「该信息未标注」；`手环有什么颜色`、`保温杯能装碳酸饮料吗` 也未被填入假值。
- 说明：手工这几次模型自己答对了，后校验没有触发；它在这里是兜底，不是主要路径。

| 误转人工率 | 0.0%（0/99） | 0.0%（0/99） |
| 答非所问率 | 2.2% | 3.0% |
| 幻觉率 | 11.8%（2/17） | 11.8%（2/17） |
| badcase | 3 条 | 4 条 |

回退如实说明：多出的 1 条是 `尾号 8821 有两个订单吗`，回答「共有两个订单」但没列出订单号 `EC20241108001 / EC20241107002`，属于回答完整性问题，与本轮后校验无关（该问题不涉及 specs、也没有「未标注」）。其余 3 条与 V2 相同（`我的订单到哪了` 与测试期望的设计取舍、写诗、1+1）。单次评测有波动，V2 与 V3 的 0.7 个百分点差异不能证明后校验有害，也不能证明有益；它的价值在于把「数据有、模型不敢答」变成确定性行为。

## 12. 已知限制

- 会话、售后单都存在进程内存里，服务重启即丢失，不适合多进程部署（`uvicorn --workers > 1` 会导致会话不共享）。
- mock 数据是写死的 4 个订单，退款只会改内存状态，不会真正对接支付/订单系统。
- 本地演示引擎是「规则 + 关键词」，复杂、口语化的问法可能识别不到；真实模型模式下由大模型按分支提示词作答，能力上限取决于所选模型。
- 转人工只生成工单摘要并展示，没有对接真实人工客服系统。
- 当前智谱账号的 `embedding-3` 返回 `429 / 1113 余额不足`，向量检索自动降级 BM25；`glm-4-flash` 对话不受影响。充值资源包后重启即切回向量检索，真实语义效果仍需在充值后复测（代码路径已用桩 embedding 验证通过）。
- DeepSeek 预设没有 embedding 模型，使用它时会自动降级为 BM25；需要向量检索请用 zhipu / dashscope，或在 `custom` 模式下自行配置 `EMBEDDING_MODEL`。
- 真实接口适配层已实现（Base URL + 请求头鉴权 + query 参数 + JSONPath 抽取 + 失败降级 mock），但需要你提供真实后端地址才能联调；仓库内用本地桩服务验证过。
- 评测分四套：`eval/report.md` 是**演示模式（规则引擎 + BM25）**、`eval/report_live.md` 是**真实模型 V1**、`eval/report_live_v2.md` 是**加「未标注即拒答」约束的 V2**、`eval/report_live_v3.md` 是**再加确定性后校验的 V3**。口径相同但实现不同，不可直接比较（详见 10.6–10.8）。`0 幻觉` 只在规则引擎下成立；真实模型剩余的 11.8% 来自闲聊越界，不是商品参数编造。
- 意图识别在演示模式下靠 `config/rules.json` 的关键词组，边界之外的长尾说法可能归错分支，需通过 badcase 持续补规则。
- 未实现用户鉴权、限流和敏感词过滤，仅适合本地演示。

## 13. 常见问题

**Q：页面打开是空白 / 一直显示"服务未连接"？**
先确认终端里服务已启动且没有报错，再访问 `http://127.0.0.1:8000/health`。如果端口不是 8000，直接用 `logs\server_url.txt` 里的地址。直接用浏览器打开 `static\index.html` 时，页面会自动探测 8000–8004 端口。

**Q：启动报 `ModuleNotFoundError: fastapi`？**
说明用的是系统 Python 而不是虚拟环境，执行 `.\.venv\Scripts\python.exe -m app.main`。

**Q：填了 Key 还是演示模式？**
看 `/health` 的 `mode` 字段；确认 `.env` 在项目根目录且 `API_KEY` 非空，改完要重启服务。模型接口报错时日志会打印 HTTP 状态码和返回体。

**Q：端口被占用怎么办？**
程序会自动顺延端口；也可以直接在 `.env` 里写 `PORT=8010`。

**Q：能换成别的模型吗？**
`PROVIDER=custom` + `OPENAI_BASE_URL` + `MODEL_NAME`，只要是 OpenAI 兼容的 `/chat/completions` 并支持 tools 即可。
